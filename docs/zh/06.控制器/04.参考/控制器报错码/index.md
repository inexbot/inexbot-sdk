# 控制器报错码

控制器在运行、通信、工艺执行过程中会上报消息码。本目录把**控制器侧的消息码**按模块整理成 6 页，共 974 条。

::: tip 一套码，多处共用

这套码由**控制器产生**，上位机 SDK（C++、C#、Python 三套语言）与控制器 SDK（`NRC_*` 接口）拿到的都是同一套码值和同一份消息文本，**不要按语言各建一份**。C# 与 Python 的《错误码表》页都指向本目录。

:::

::: tip 与 SDK 返回值的区别

本目录讲的是**控制器上报的消息码**（4~5 位十进制，如 `4097`、`9249`），它通过消息回调送到上位机。
SDK 接口自身的返回值是另一套：上位机 C++ 为 `Result`（`0`、`-1` ~ `-6`），控制器 SDK 为 `0` / `-101` / `-102` / `-103`。见[错误码表](../错误码表.md)。**两者不要混用**：接口返回成功不代表控制器没有上报消息。
:::

## 怎么拿到这些码

订阅控制器的错误/警告消息回调，回调里的 `messageCode` 就是本目录的**十进制码值**：

```cpp
Result set_receive_error_or_warnning_message_callback(
    SOCKETFD socketFd,
    void (*function)(int messageType, const char* message, int messageCode));
```

- `messageType`：消息级别（错误 / 警告 / 信息）
- `message`：消息文本，与本目录「消息文本」列一致（`%d`、`%i` 会被替换为机器人编号）
- `messageCode`：本目录的十进制码值

现场反馈问题时，让客户提供**界面上显示的码值**即可，不必给十六进制。

## 消息里的 `%d`、`%s` 怎么读

本目录的「消息文本」列是**代码里的格式串**，不是界面上的最终文字：

| 格式符 | 会被替换成 |
| ------ | ---------- |
| `%d`、`%i` | 机器人编号（多机时有用） |
| `%s` | 具体对象名称：轴名、设备名、IO 名称、变量名等 |
| `%f`、`%0.2f` | 数值（速度、位置、力矩等） |

回调的 `message` 参数拿到的就是**替换完成的完整句子**，界面弹窗显示的也是它。排查时以这句原文为准，不要拿格式串去比对。

少数码的消息文本整句都由控制器拼装（表中显示为「由控制器拼装，界面显示实际内容」或「`指令[指令码]` ＋ 具体原因」）。这类码没有固定文案，**处理建议里已经写明该看原文的哪一部分**——例如按 `message` 里出现的 IO 名称去核对配置，或按指令码去作业文件里定位那一行。

## 级别的含义

| 级别 | 含义 | 现场处理 |
| ---- | ---- | -------- |
| 错误 | 触发保护或中断当前动作 | 必须处理，多数会阻止继续运行 |
| 警告 | 不中断运行，但状态异常 | 记录并观察，反复出现需排查 |
| 信息 | 状态变更通知（如急停解除） | 仅记录，无需处理 |
| 未标注 | 代码中未登记级别 | 按错误对待，联系技术支持确认 |

## 查不到码怎么办

1. **先确认码值位数**：本目录是控制器消息码（4~5 位）。4 位且形如 `7500`、`5410` 的码可能来自**伺服驱动器**或安全模块，不在本目录内。
2. **按消息文本反查**：把界面上的提示文字在本目录内搜索，比按码值更容易命中。
3. **确认版本**：不同版本的码值可能新增或调整，对照[版本与兼容性](../../../版本与兼容性.md)确认交付包与控制器版本匹配。
4. 仍查不到时，提供**码值 + 消息原文 + 控制器版本 + 复现步骤**给技术支持。

::: warning 关于「预留码」

少数码在代码中已定义但当前版本未上报（如部分段内的跳号），这类码不会出现在界面上，属正常情况，不必排查。
:::
