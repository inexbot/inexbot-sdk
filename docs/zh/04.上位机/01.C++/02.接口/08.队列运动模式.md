# 八、队列运动模式（nrc_queue_operate.h）

## 使用说明

队列运动把运动指令在**上位机本地**组装成队列，再一次性推给控制器执行，不需要作业文件。典型场景是视觉或外部传感器给出连续轨迹、边算边发。

流程：`queue_motion_set_status(true)` → 逐条 `queue_motion_push_back_*` → `queue_motion_send_to_controller` → 轮询完成 → `queue_motion_stop_not_power_off` / `queue_motion_set_status(false)`。

要点：

- **前置**：伺服已进入状态 3、机器人处于停止状态、控制器当前没有其他队列或运动任务。
- **上电完成怎么判**：`set_servo_poweron` 返回 0 只代表命令已下发，必须轮询 `get_servo_state` 直到等于 3（运行）再下发队列，否则首段轨迹会被吞掉。
- **清空**：开启或关闭队列模式都会清空控制器已有队列，不要在别的任务运行时开关。
- **发送**：`queue_motion_send_to_controller(size, isContinue)`，`size` 取值 `[0,31]`，`0` 表示全部发送；`size` 超过当前队列长度返回 `-3`。
- **`isContinue` 的语义**（决定机器人什么时候动）：
  - `false`（默认）：控制器收到点位后**立刻开始运动**；
  - `true`：只收点不运动，可继续用 `isContinue=true` 追加，最后用一次 `isContinue=false` 触发运动。
- **停止**：优先 `queue_motion_stop_not_power_off`（保持上电），再关闭队列模式。
- **不要与追加运行模式混用**：两者都往控制器塞指令，同时开启会互相打断，表现是「队列开了、机器人不动」。
- **点位引用方式**：队列里的 `MoveCmd` 用 `targetPosValue` 直接给数值；`targetPosName`（`AP`/`GP`/`P` 变量）只在作业文件运行模式下有效（头文件注释：*单独的 Movj 只能使用数值，作业文件运行模式只支持使用变量*）。

::: tip 单次下发多少点
接口注释允许 `[0,31]`，但现场经验是**单次不超过约 20 个点**更稳，超过后出现过控制器收到异常数据的情况。大批量轨迹建议分批发送并轮询队列长度。
:::

::: tip 与其他下发方式的区别
队列运动只是上位机两条下发通道之一（另一条是作业文件按行插入）。作业文件插入，以及控制器侧「运行中追加」的对比，见[接口说明首页的「实时运动下发」一节](./index.md)。
:::

::: tip 队列轨迹和示教器走出来的不一样？按这个顺序查
多数不是算法问题，而是点位属性不一致：
1. `configuration`（形态）：同一个 TCP 位置可能有多个关节解，形态不同 → 姿态不同；
2. `toolNum` / `userNum`：与机器人当前工具手 / 用户坐标不一致会**直接报错**（一致时才按该坐标换算）；
3. `coord`：0 关节 / 1 直角；直角点位在换工具后轨迹会变；
4. `velocity` / `acc` / `pl`：平滑等级不同，拐角外形会差；
5. 外部轴：`parasync` 未开启，或 `targetPosValue` 后 7 位未填，外部轴不联动。
:::

::: tip 别用「剩余指令数 = 0」判断跑完
队列**尚未启动**时剩余指令数同样是 0，会被误判为「已完成」。判断条件建议同时满足：队列模式全程保持开启、机器人确实进入过运行状态（或剩余数曾大于 0）、最终剩余数为 0 且运行状态为 0；只看到「剩余 0」时，连续多次确认停止状态再下结论。
:::

### `MoveCmd` 参数（moveJ / moveL / moveC 共用）

`push_back_move*` 系列都收一个 `MoveCmd`（`nrc_define.h`），字段如下：

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `targetPosType` | `PosType` | `data(0)` | 点位类型：`data`＝自定义数组，`P/AP/GP/GE`＝系统点位 |
| `targetPosValue` | `vector<double>` | 长度 14 | 目标位置。**前 7 位本体关节，后 7 位外部轴**；`data` 类型必须填 |
| `targetPosName` | `string` | 空 | 用系统点位时填名称，如 `"GP0001"`（仅作业文件模式有效） |
| `coord` | `int` | 0 | 坐标类型：0 关节 / 1 直角 / 2 工具 / 3 用户 |
| `velocity` | `double` | 50 | 速度。**单位随指令变化**：MovJ 系为百分比 `(1,100]`，MovL/MovC/MovS/cil 等为 `mm/s` `(1,1000]`，`imove`/`samov` 跟随点位坐标，见下方说明 |
| `velocitySync` | `double` | 0 | 外部轴速度同步值 |
| `acc` / `dec` | `double` | 50 | 加速度 / 减速度，统一为百分比 `(1,100]` |
| `pl` | `int` | 0 | 平滑等级 |
| `time` | `int` | 0 | 提前执行时间 |
| `toolNum` | `int` | 0 | 该点位使用的**工具手编号**；运行时机器人当前工具手与此不一致 → 报错 |
| `userNum` | `int` | 0 | 该点位使用的**用户坐标编号**；运行时机器人当前用户坐标与此不一致 → 报错 |
| `configuration` | `int` | 0 | 形态（关节解的分支） |
| `posidtype` | `int` | 0 | 0＝一级变量（`GP0001`），1＝二级变量（`GP[I001]`） |
| `spin` | `int` | 0 | 仅 MOVCA 用：0 姿态不变 / 1 六轴不转 / 2 六轴旋转 |
| `parasync` | `bool` | false | 外部轴是否同步 |

::: warning `velocity` 只有一个字段，但单位随指令变
所有 `push_back_move*` 共用 `MoveCmd` 的同一个 `velocity` 字段，**填的是什么单位完全由指令决定**，混用会得到完全不同的速度（例如给 MovL 填 50 是 50 mm/s，而给 MovJ 填 50 是 50%）：

| 指令 | `velocity` 单位 | 取值 |
|------|----------------|------|
| `moveJ` / `moveJ_extra` | **百分比**（关节满速的百分数） | `(1,100]` |
| `moveL` / `moveL_extra` | `mm/s` | `(1,1000]` |
| `moveC` / `moveCA` | `mm/s` | `(1,1000]` |
| `moveS` | `mm/s` | `(1,1000]` |
| `EImoveL` / `EImoveC` / `EImoveCA` | `mm/s` | `(1,1000]` |
| `cil` | `mm/s` | `(1,1000]` |
| `imove` / `samov` | **跟随点位坐标**：点位是关节坐标 → 百分比；否则 → `mm/s` | 按单位同左 |
| `push_moveComm` | 按 `moveType` 字符串：`"MovJ"` → 百分比，`"MovL"` → `mm/s` | 按单位同左 |

`acc` / `dec` 在所有指令下都是百分比 `(1,100]`。

补充：
- 头文件对 MovJ 的 `velocity` 注释写的是「度/s」，**实际按百分比填**（`50`＝满速 50%）；MovL 系则是实打实的 `mm/s`。两处别按字面理解反了。
- `imove` / `samov` 的速度单位由点位坐标决定：目标点是关节坐标时按百分比，是直角等笛卡尔坐标时按 `mm/s`。`cil` 恒为 `mm/s`。
- `conveyor_on` 的速度不是 `MoveCmd` 里的字段，而是独立入参 `vel`：`[2,2000] mm/s`，`acc` 为 `[1,100]` %。
:::

::: warning 工具手 / 用户坐标必须与机器人当前值一致，否则运行时报错
`MoveCmd.toolNum` / `userNum` 是**该点位所属的工具手编号和用户坐标编号**，不是「用不用工具」的开关。编号 **`0` 表示「无工具手 / 无用户坐标」**（等价于示教时选「无」），不是继承当前值。
运行到这个点时，控制器会比对机器人当前的工具手 / 用户坐标：
- **一致**：正常执行，按该工具/用户坐标换算；
- **不一致**：**直接报错**（提示形如「机器人1工具坐标使用错误，点位工具为1，实际使用工具2」），不会自动切换。

因此队列里的点位要用哪把工具、哪个用户坐标，就把对应编号显式填进去；不要在示教器上临时切了工具/用户坐标再跑同一条队列。切换后要么同步修改队列里的编号，要么重新下发。
:::
