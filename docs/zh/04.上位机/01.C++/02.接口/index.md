## 通用约定速查

以下规则**跨模块通用**，各具体接口页不再重复；权威细则见「细则」列。

| 主题 | 约定 | 细则 |
| ---- | ---- | ---- |
| 返回值 | 只认 `SUCCESS(0)`。`-2` 优先查句柄来源、`-4` 优先查前置状态、`-6` 优先查链路与负载 | [错误码表](../04.参考/错误码表.md) |
| 端口与句柄 | 6001 主连接 / 7000 伺服跟踪 / 6000 示教；**句柄与端口绑定，混用返回 `-2`** | [头文件与端口说明](./00.头文件与端口.md) |
| 单位口径 | 关节角为**度**、姿态为**弧度**、X/Y/Z 为 **mm**、速度为 **%**；接口不返回单位标志 | [核心概念](../01.文档/03.核心概念.md) |
| 坐标系参数 | `coord`：0=关节 1=直角 2=工具 3=用户 | [数据结构定义](../04.参考/数据结构.md) |
| 点位工具/用户坐标 | `MoveCmd.toolNum` / `userNum` 是**该点位**的工具手 / 用户坐标编号；运行时与机器人当前值不一致会**报错**，不自动切换 | [数据结构定义](../04.参考/数据结构.md) |
| 机器人编号 | `robotNum` 取 1-4，仅 `_robot` 版本需要 | 各接口条目 |
| 轴号索引 | 各接口 0/1 起始**未统一标注**，涉及轴控制时先用回读接口验证 | 待核 |

::: tip 返回值只有三种形态，判定方式不能互相套用

- `Result`：绝大多数操作类接口（上下电、模式、作业、队列、IO…），判 `== SUCCESS`。
- `SOCKETFD`：`connect_robot`，≥0 为句柄、`-1` 为失败（这个 `-1` 不是 `Result` 的 `-1`）。
- `bool` / 出参：查询类接口，判返回值并校验出参是否被填充。
:::

### 调用前自检

1. **连接**：`connect_robot` 返回句柄，且 `get_connection_status` 正常。
2. **伺服**：`get_servo_state` 为状态 3（已使能）；未使能先 `set_servo_poweron`，失败排查见[基础连接与系统接口](./01.基础连接与系统接口.md)。
3. **模式**：`get_current_mode` 与接口要求一致（部分接口要求运行/远程模式，队列运动三种模式语义不同）。
4. **坐标与速度**：`get_current_coord` / `get_speed` 已设置，速度和倍率符合预期。
5. **前置状态**：队列类接口要求先 `queue_motion_set_status(true)`；作业类接口要求作业已打开或文件已上传。

生命周期与状态机参见[核心概念](../01.文档/03.核心概念.md)。

### 调用后自检

- **运动类**：回读 `get_current_position` 与目标比对；确认 `get_robot_running_state` 已回到停止。
- **队列类**：`queue_motion_get_status` 确认模式、`queue_motion_size` / `queue_motion_get_queuelen` 确认队列已排空，再关闭队列。
- **作业类**：`job_get_current_file` / `job_get_current_line` 确认作业与行号符合预期。
- **IO 类**：读回输出点状态，不要只依赖写接口返回值。

### 高频失败对照

| 现象 | 优先排查 | 详见 |
| ---- | -------- | ---- |
| 返回 `-2` | 句柄是否来自正确端口；连接是否已被对端关闭 | [错误码表](../04.参考/错误码表.md) |
| 返回 `-6` | 链路中断、控制器负载高、单次指令量过大 | [错误码表](../04.参考/错误码表.md) |
| 返回 `-4` | 未上电、模式不对、队列未开启 | 上方「调用前自检」 |
| 上下电失败 `RECEIVE_FAILED` | 伺服状态或控制器异常 | [基础连接与系统接口](./01.基础连接与系统接口.md) |
| 队列开启后机器人不动 | 未 `queue_motion_send_to_controller`；或把队列模式与追加运行模式混用 | [队列运动模式](./08.队列运动模式.md) |
| 断点续跑失效 | 断点被清除（11 类条件） | [作业文件操作 §7.9](./07.作业文件操作.md) |

## 实时运动下发：上位机能用哪几种方式

上位机 SDK（`nrc_*.h`）往控制器送运动指令有**两条**通道；第三条「运行中追加」属**控制器侧 API**（`NRC_*`，见[控制器 · 作业文件-指令操作](../../../06.控制器/02.接口/02.作业文件-指令操作.md)），需要控制器二次开发，不在本 SDK 内。**选错通道是最常见的一类现场问题**：指令发出去了、机器人不动或者被打断，往往不是接口坏了，而是模式与通道不匹配。

| | A. 队列运动模式 | B. 作业文件按行插入 | C. 运行中追加（控制器侧） |
| -- | -- | -- | -- |
| 所属 SDK | 上位机 `nrc_queue_operate.h` | 上位机 `nrc_job_operate.h` | 控制器 `NRC_*`，需控制器二开 |
| API 家族 | `queue_motion_*` | `job_insert_*` | `NRC_OpenInstrAppendRunMode` → `NRC_AppendRunInstr` 等 |
| 是否需要作业文件 | 不需要，队列在本地组装 | 需要，写入指定作业文件 | 需要已开启追加运行模式 |
| 实时性 | 发送即执行 | 只改文件，运行时不生效 | 添加后立即执行，可连续追加 |
| 打开/关闭的影响 | 开启或关闭都会**清空控制器已有队列** | 不影响运行中的作业 | 打开/关闭追加模式会**自动上下使能**，停止会清空全部队列 |
| 典型场景 | 视觉/外部实时轨迹、连续小段路径 | 程序预编排、批量生成作业 | 边跑边补指令、暂停后插入新动作 |

::: warning `nrc_*` 与 `NRC_*` 是两个 SDK，不要混用

- **小写 `nrc_*.h` + 小写函数名**（`connect_robot` / `job_run` / `queue_motion_*`）= **上位机 SDK**，跑在 PC 上，通过 6001/7000 端口连控制器。本站「04.上位机」全部是这一套。
- **大写 `NRC_*`** = **控制器二次开发 API**，跑在控制器内部，见[06.控制器](../../../06.控制器/02.接口/index.md)。

在上位机程序里找不到 `NRC_AppendRunInstr` 一类接口是正常的 —— 想用「运行中追加」，要么改走控制器二开，要么用 B（作业文件插入）替代。

注意别被名字绕进去：上位机示例里的**「追加队列模式」**（见[示例 09](../03.示例/02.基础应用/09.追加队列模式（单机器人）.md)）指的就是下面的 A —— 开队列、往本地队列 push、再整批发出去，与控制器侧的「运行中追加」不是一回事。
:::

| 你的场景 | 选哪个 |
| -------- | ------ |
| 视觉给出连续轨迹，边算边发 | A 队列运动模式（分批，轮询队列长度） |
| 离线生成一批固定程序 | B 作业文件插入，再整体运行 |
| 程序已在跑，中途插入新动作 | B（上位机）；要真正「边跑边加」需 C，即控制器二开 |
| 需要毫秒级关节流式控制 | `open_servoJ` / `set_servoJ_pos`（7000 端口）；已有整段点可一次给，用 `open_servoJ_queue_mode` + `append_servoJ_pos_to_queue`，见[使用 servoJ 进行关节控制](../03.示例/03.进阶应用/03.使用servoJ进行关节控制.md) |
| 只是改几个点位后重跑 | B |

- **A 的调用流程**、清空语义、单次点数上限与停止方式，见[队列运动模式](./08.队列运动模式.md)。
- **B 的插入生效时机**与行号变化，见[作业文件操作](./07.作业文件操作.md) §7.5。
- **C 的使能、暂停约束与崩溃风险**，见[控制器 · 作业文件-指令操作](../../../06.控制器/02.接口/02.作业文件-指令操作.md)。
