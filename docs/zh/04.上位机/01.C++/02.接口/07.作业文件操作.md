# 七、作业文件操作（nrc_job_operate.h）

## 功能概述

作业文件（.JBR）是控制器的核心程序文件，由多条指令组成。本模块提供作业文件的上传/下载/新建/删除/打开、运行控制（运行/单步/暂停/继续/停止）、内容读取与编辑（按行查询/删除/插入指令）等完整操作能力。

**作业文件生命周期：** 上传/新建 → 打开 → 编辑（插入/修改指令）→ 运行 → 暂停/继续 → 停止

## 7.1 作业文件管理

### job_get_all_jobfile_name

获取所有作业文件名。

**函数原型：**

```cpp
Result job_get_all_jobfile_name(SOCKETFD socketFd, std::vector<std::vector<std::string>>& robotsFile);
```

**参数说明：**

| 参数 | 类型 | 说明 |
|------|------|------|
| socketFd | SOCKETFD | 连接句柄 |
| robotsFile | std::vector\<std::vector\<std::string\>\>& | 输出参数，二维数组，一维长度 4，对应 4 个机器人的作业文件列表 |

**返回值：** `SUCCESS(0)` 表示成功，负数表示失败。

**使用示例：**

```cpp
std::vector<std::vector<std::string>> files;
Result result = job_get_all_jobfile_name(fd, files);
if (result == SUCCESS) {
    printf("机器人1的作业文件: \n");
    for (const auto& name : files[0]) {
        printf("  %s\n", name.c_str());
    }
}
```

## 7.5 运动指令插入

向作业文件指定行号插入运动指令，所有接口均提供 `_robot` 版本。

**插入只改文件，不影响正在运行的程序**：插入完成后需要重新运行作业才生效。行号会随插入/删除变化，批量插入时建议从后往前插，或每插一条重读 `job_get_command_total_lines`。

| 接口 | 指令 | 说明 |
|------|------|------|
| `job_insert_moveJ` | MoveJ | 关节运动指令 |
| `job_insert_moveL` | MoveL | 直线运动指令 |
| `job_insert_moveC` | MoveC | 圆弧运动指令 |
| `job_insert_imove` | IMOVE | 增量运动指令（`moveCmd.targetPosType = 3`，`moveCmd.targetPosName = "RP0001"`） |
| `job_insert_moveComm` | moveComm | 外部点指令，`moveType` 为插补方式 `"MovJ"`/`"MovL"`，参数含速度/加速度/减速度/时间/平滑度 |
| `job_insert_samov_command` | SAMOV | 定点移动指令（点位数据用 PositionData） |
| `job_insert_EImoveL` | EImoveL | 外部轴直线运动 |
| `job_insert_EImoveC` | EImoveC | 外部轴圆弧运动 |
| `job_insert_EImoveCA` | EImoveCA | 外部轴圆弧绝对运动 |

**moveJ/moveL/moveC 函数原型：**

```cpp
Result job_insert_moveJ(SOCKETFD socketFd, int line, MoveCmd moveCmd);
Result job_insert_moveL(SOCKETFD socketFd, int line, MoveCmd moveCmd);
Result job_insert_moveC(SOCKETFD socketFd, int line, MoveCmd moveCmd);
```

**moveComm 函数原型：**

```cpp
Result job_insert_moveComm(SOCKETFD socketFd, int line, std::string moveType, double m_vel, double m_acc, double m_dec, int m_time, int m_pl);
```

**使用示例（插入 MoveJ 指令）：**

```cpp
MoveCmd cmd;
cmd.coord = 0;          // 关节坐标
cmd.velocity = 80;      // 速度 80%
cmd.acc = 50;
cmd.dec = 50;

// 在第 5 行插入 MoveJ 指令
Result result = job_insert_moveJ(fd, 5, cmd);
```

## 7.6 延迟、IO、逻辑控制指令插入

| 接口 | 指令 | 说明 |
|------|------|------|
| `job_insert_timer_command` | TIMER | 延时指令，`time` 单位秒 |
| `job_insert_io_out_command` | IO_OUT | IO 输出指令，参数 `IOCommandParams` |
| `job_insert_until` | UNTIL | 直到循环开始（条件组 + 逻辑类型） |
| `job_insert_end_until` | END_UNTIL | 直到循环结束 |
| `job_insert_while` | WHILE | 条件循环开始 |
| `job_insert_end_while` | END_WHILE | 条件循环结束 |
| `job_insert_if` | IF | 条件判断开始 |

## 7.9 断点与续跑

断点续跑能省掉现场重新对位的时间，但**断点什么时候会丢**一直没有成文口径，导致「昨天还能续跑，今天不行」。本节说明断点的产生、清除条件、续跑与从头启动。

::: tip 上位机侧只有续跑入口，断点由控制器管理
断点是**控制器侧状态**，清除条件由控制器决定。本节涉及的 `NRC_*` 接口属**控制器二开 API**（不在 `nrc_*.h` 里），见[控制器 · 作业文件-指令操作](../../../06.控制器/02.接口/02.作业文件-指令操作.md)；上位机侧的续跑入口只有 `job_break_point_run`。
:::

### 断点是什么

- 作业运行过程中，控制器会记录「当前作业文件 + 当前行号 + 运行上下文」，用于中断后从原位置继续。
- 断点属于**控制器侧状态**，不是上位机保存的；上位机断开连接、重启程序不会清除断点。
- 是否允许续跑，取决于断点是否仍然「有效」（见下方「旧断点失效」）。

### 断点清除条件

下表为现场确认口径，按触发类型分组。**固件版本不同可能有增删，升级后请以实测为准。**

**一、正常与人工操作**

| 条件 | 说明 |
| ---- | ---- |
| 作业正常运行结束 | 跑完即无断点 |
| 急停，且配置了 IO 复位 | 复位动作会清断点 |
| 在示教器上导入程序 | 覆盖作业内容 |
| 使用 `startOver=true` 从头启动 | JSON 协议重头运行见[程序运行控制](../../../05.JSON-协议/03.RTL-25.01/01.协议/03.程序/05.程序运行控制.md) |
| 回复位点 / 执行复位程序 | 现场恢复流程的一部分 |

**二、旧断点失效**（断点还在，但判定为不可恢复）

出现任一情况，控制器不再允许从旧断点续跑：

- 没有原运行上下文（控制器重启后上下文丢失）；
- 作业文件名不一致；
- 断点行号小于 1；
- 当前行所属作业与断点记录的作业不一致；
- 断点保存模式与当前模式不同；
- 调用程序或子程序被修改；
- 工艺状态不允许恢复。

**三、异常与失败**

| 条件 | 说明 |
| ---- | ---- |
| 作业打开失败、文件为空、语法错误、插补错误等异常退出 | 运行未正常建立 |
| 断点续跑计算失败或恢复超时 | 续跑请求本身失败 |

**四、配置与模式变更**

| 条件 | 说明 |
| ---- | ---- |
| 修改机型、轴映射、DH、关节参数 | 机器人对象重建，断点上下文失效 |
| 切换追加运行等特殊模式 | 与作业运行上下文不兼容 |

**五、接口主动触发**

| 条件 | 说明 |
| ---- | ---- |
| 自定义错误 `NRC_TriggerErrorReport`（**控制器侧接口**） | 会主动发送清断点命令，见[控制器 · 作业文件-指令操作](../../../06.控制器/02.接口/02.作业文件-指令操作.md) |
| 带「保留断点」语义的错误上报接口（控制器侧） | 按版本提供，是否可用见本节「版本差异与待核」 |

### 续跑与从头启动

| 需求 | 做法 | 说明 |
| ---- | ---- | ---- |
| 从中断位置继续 | `job_break_point_run(jobName)` | **需要运行模式**，见 §7.3 |
| 从头重新跑 | `job_run` + JSON 协议 `startOver=1` | C++ 接口无 `startOver` 参数，重头运行走 JSON 协议或先停止再运行 |
| 只跑一步 | `job_step` | 调试用，不产生可续跑断点 |

::: tip 判断能否续跑
先确认两件事：作业文件没被改过（内容/子程序）、机器人配置没动过。这两条命中「旧断点失效」或「配置与模式变更」的任一条件，续跑都会失败，直接从头跑更快。
:::

### 常见场景处置

| 场景 | 建议动作 |
| ---- | -------- |
| 客户现场断电后想续跑 | 控制器重启会丢上下文，按「旧断点失效」判断；不行就从头跑并检查安全点位 |
| 示教点位改了，想接着跑 | 改点位属于修改作业，断点失效，需从头运行 |
| 报错提示后作业停了，想续跑 | 若用的是 `NRC_TriggerErrorReport`，断点已被清除；改用保留断点的上报方式（按版本） |
| 换了机器人配置/换了机型 | 断点必然失效，重新运行 |
| 续跑接口返回失败 | 先用 `job_get_current_file` / `job_get_current_line` 看当前状态，再决定是否从头运行 |

### 相关接口

| 接口 | 用途 | 前置 |
| ---- | ---- | ---- |
| `job_run` / `job_run_robot` | 运行作业 | 作业已上传 |
| `job_step` | 单步 | 运行模式 |
| `job_pause` / `job_continue` | 暂停 / 继续 | 作业运行中 |
| `job_stop` | 停止 | — |
| `job_run_times` | 设置循环次数 | `0=无限次` |
| `job_break_point_run` | 断点续跑 | **运行模式** |
| `job_get_current_file` / `job_get_current_line` | 查当前作业与行号 | — |

### 版本差异与待核

- 「保留断点的错误上报」接口（`NRC_TriggerErrorReportKeepBreakpoint`）在客户群中已被提及为新增能力，但**当前仓库文档与头文件中尚未收录**，使用前请向研发确认所在版本，不要按本节描述直接调用。
- 断点清除条件清单来自现场核对，个别条目（如「切换追加运行」）与固件版本相关，升级后建议回归验证。
- 断点是否跨控制器重启保留，各版本行为不一致，属待补项。
