# 4. 断开连接

本期介绍如何规范地释放与控制器之间的连接。断开连接是每个控制程序的收尾动作，必须在 `finally` 中执行，避免异常路径导致连接未释放。

::: warning 连接数量限制
同一控制器支持的并发 SDK 连接数量有限。程序异常退出但未断开连接时，连接会在一段时间内保持占用（实测约 2 分钟后自动释放）。排查「连不上」问题时，应优先确认是否存在未释放的旧连接。
:::

## 1、配置连接与断开参数

```python
# ===== 用户需要修改的部分 =====
ip   = "192.168.3.239"
port = "6001"

# ===== 重试与等待参数 =====
CONNECT_RETRY_COUNT    = 5    # 连接失败后的最大重试次数
WAIT_CONNECT_RETRY     = 1    # 连接失败后的等待时间（秒）
WAIT_ROBOT_TASK        = 2    # 模拟机器人任务的执行时间（秒）
DISCONNECT_RETRY_COUNT = 3    # 断开连接失败后的最大重试次数
WAIT_DISCONNECT_RETRY  = 0.5  # 断开连接失败后的等待时间（秒）
```

`WAIT_ROBOT_TASK` 仅用于模拟任务耗时；替换 `robot_task()` 内部流程后，该参数通常不再使用。

## 2、封装返回值检查与连接函数

```python
def check_result(result, name):
    if result != 0:
        raise Exception(f"{name}失败,返回值:{result}")

def connect_robot():
    for i in range(CONNECT_RETRY_COUNT):
        socketFd = nrc_interface.connect_robot(ip, port)
        if socketFd > 0:
            print("机器人连接成功")
            return socketFd
        print(f"第{i+1}次连接失败，等待重试")
        # 连接失败后等待一段时间，避免在控制器尚未准备好时连续快速建立连接
        time.sleep(WAIT_CONNECT_RETRY)
    raise ConnectionError(f"连续{CONNECT_RETRY_COUNT}次连接机器人失败")
```

## 3、封装断开连接函数

断开属于程序结束阶段，单次失败可能只是瞬时通信异常，因此同样做有限次重试：

```python
def disconnect_robot(socketFd):
    if socketFd:
        for i in range(DISCONNECT_RETRY_COUNT):
            result = nrc_interface.disconnect_robot(socketFd)
            if result == 0:
                print("机器人连接关闭")
                return
            print(f"第{i+1}次断开连接失败,返回值:{result}")
            if i < DISCONNECT_RETRY_COUNT - 1:
                time.sleep(WAIT_DISCONNECT_RETRY)
        raise Exception(f"连续{DISCONNECT_RETRY_COUNT}次断开机器人连接失败")
```

注意 `if socketFd:` 判断：连接未成功建立时句柄为空，直接调用断开接口会返回错误。

## 4、模拟机器人任务

`robot_task()` 只是占位，实际项目中替换为运动、IO、作业执行等具体流程。`socketFd` 作为参数保留，便于后续直接加入 SDK 控制指令：

```python
def robot_task(socketFd):
    print("机器人任务执行中")
    # 使用固定的模拟任务等待时间，避免真正控制机器人，仅用于演示任务执行流程
    time.sleep(WAIT_ROBOT_TASK)
    print("机器人任务执行完成")
```

## 5、完整执行流程

```python
def main():
    socketFd = None
    try:
        socketFd = connect_robot()
        print("连接成功 socketFd =", socketFd)

        robot_task(socketFd)
        print("Demo执行成功")
    except KeyboardInterrupt:
        print("用户主动终止程序")
    except Exception as e:
        print("Demo执行异常:", e)
    finally:
        if socketFd:
            try:
                # 无论任务执行是否出现异常，都尝试断开机器人连接，保证通信资源得到释放
                disconnect_robot(socketFd)
            except Exception as e:
                # 断开连接本身发生异常时进行提示，但不再重复抛出异常影响程序退出
                print("断开连接异常:", e)
```

两层保护值得注意：

- `finally` 保证任何退出路径都会尝试断开
- `try/except` 包住 `disconnect_robot`，避免断开失败覆盖掉真正的业务异常

完整可运行脚本见 devkit：`04-上位机/Python/RTL-24.03（当前）/04-示例/基础示例/04-断开连接/04_disconnect.py`。

## 常见问题

- **断开返回非 0：** 句柄可能已被对端关闭，Demo 重试 3 次后抛异常；若程序已进入退出流程，可只打印告警不中断
- **重复运行后连不上：** 上一次程序被强杀，连接尚未释放，等待约 2 分钟后重试
- **忘记断开的影响：** 连接数被占满后新连接请求会被拒绝，表现为 `connect_robot` 持续返回非正值
